v1の既知の制限(今後の課題):
- 和了牌は必ず確定が必要(不明ツモのままの和了は先に「?」を埋める)
- 進行中(未終了)の局は保存に含まれない(局終了ごとに自動保存)

Mリーグルール適合レビュー(2026-07-30)で対応済み:
責任払い(パオ: 大三元・大四喜・四槓子、ツモ全額/ロン折半)、天和・地和の自動判定、
嶺上開花と海底摸月の非複合、ロンは頭ハネで1人のみ(公式「アガリ者は一局に1人」・
ダブロン入力は廃止)、海底牌でのリーチ禁止、
南4局で親が流れたら終了(西入なし)、カンは4回まで・山0では不可、
局の途中で精算しても未保存局のリーチ棒は供託に混ざらない。

放送対局(Mリーグ等)を見ながら、タップ操作だけで牌譜を記録する機能。
出来た牌譜は既存の牌譜ビューア(リプレイ・お気に入り・ゴースト)でそのまま見られる。

## 0. 前提の整理: 放送で「見えるもの」(2026-07-28 実態確認済み)

Mリーグ放送(ABEMA)は実物の牌を使った対局の**実写映像**であり、手牌や打牌のCG表示は無い。
画面上の常時グラフィックは「全選手のポイント・リーチ状態・聴牌時の待ち牌・**ドラ牌そのもの**」。

| 情報 | 見え方 | 記録方法 |
|---|---|---|
| 打牌 | 実写のみ(河全体が完全に映ることはほとんどない) | 毎巡、目視で判別して入力(本機能の主作業) |
| ツモ牌・手牌 | 手番の選手の手元が映ったときだけ実写で見える | 見えた範囲で入力。見えなければ「?」 |
| ドラ | **ドラ牌そのもの**が画面に常時表示 | ドラ牌を1タップ(表示牌へは内部で逆変換) |
| 待ち牌(聴牌時) | 画面下部に表示 | 入力不要(記録の検算に使える) |
| 点数・供託・本場 | 画面表示あり | **完全自動**(Mリーグルールで計算し、画面表示と照合) |
| 和了手牌・裏ドラ | 実写のみ(開示時に映る) | 和了時に目視で入力 |
| 役・点数 | 放送でも出るが | **完全自動**(engineのevaluateWin/calcPayment) |

方針: **ユーザーが入力するのは「実写から読み取れた牌」と「宣言(ポン・ロン等)」だけ**。
点数・順番・積み棒・親移動・役判定はすべてMリーグルール実装が自動処理する。

実写のみという制約から導かれる設計原則:
1. **取りこぼし前提** — カメラが選手の顔を映している間の打牌など、読み取れない瞬間は
   必ずある。「?」(不明)をどこにでも置けて、後から埋められることを最優先する。
2. **VOD前提で精度を求める**(2026-07-29 決定) — Mリーグは生放送中でも巻き戻し・
   一時停止が可能で、過去分も後日視聴できる。止めながら写せる前提で「?」ゼロの
   完全牌譜を目指せる設計とする。ただしUI方針は**出来る限り簡略な操作**を貫く
   (操作に熟練したら止めない生放送リアルタイム記録にも挑戦できる、が到達目標)。
3. **アプリ内の河表示が照合の生命線** — 放送では河が見えないので、アプリの河が
   「ここまで記録した」の唯一の可視化になる。左パネルは河を常時表示に格上げする。

## 1. 全体像

- 記録エンジンは対戦用GameEngineとは別の軽量な**状態機械+イベントソーシング**
  (GameEngineは配牌が最初に確定している前提なので、遅延配牌と相性が悪い)。
- 局が終わるたびに `paifu_record.dart` の既存ヘルパー(tilesToDbString / callBlock /
  reach位置規約 / tプレフィックス / agari points仕様)で**本家DBスキーマ互換のJSON**
  を書き出す。保存ストアは MyPaifuStore と同型(1試合1JSON)。局が終わるたびに
  試合JSON全体を書き直す(追記ではない)。
- ビューアの入口は「🀄 自分の対局・記録した牌譜」→「✍️ 記録した牌譜」
  (自分の対局と同じグループ内の別タイル。ReplaySession は PaifuSource 抽象が
  あるので無改造で再生できる)。
- 一局のみでも一試合すべてでも記録できる(途中の局から開始可、いつでも保存終了可)。

## 2. セットアップ画面(記録開始前)

```
┌──────────────────────────────────────┐
│ ✍️ 牌譜記録                           │
│ プレイヤー名(空欄なら 東家/南家/…)      │
│  起家[ 佐々木 ] 南[     ] 西[     ] 北[     ] │
│ 開始局  [東1局▾] [0本場▾] 供託[0▾]     │
│ 持ち点  25000 / 25000 / 25000 / 25000  │
│         (東1局0本場なら自動で25000固定)  │
│              [記録をはじめる]           │
└──────────────────────────────────────┘
```

- 名前は**席順(起家から)**で入力。未入力は疑似ネーム。
- 東1局0本場供託0以外(途中の局・本場や供託がある開始)のときだけ持ち点を編集可能にする。
- 半荘戦固定(Mリーグ)。東風選択などは出さない。

## 3. 記録画面(横画面・1画面完結)

```
┌────────────────────────────────────────────────────────────┐
│ 東1局0本場 供託0 残り70 │ ガイド: 東家のツモ — 牌をタップ │ [↩︎][⋮] │
├───────────────────────────────┬────────────────────────────┤
│ ▶︎東 佐々木 25000 [河ミニ表示…] │  1m 2m 3m 4m 5m 6m 7m 8m 9m 0m │
│   南 高宮   25000 [河ミニ表示…] │  1p 2p 3p 4p 5p 6p 7p 8p 9p 0p │
│   西 松本   25000 [河ミニ表示…] │  1s 2s 3s 4s 5s 6s 7s 8s 9s 0s │
│   北 伊達   25000 [河ミニ表示…] │  東 南 西 北 白 發 中  [?不明]  │
│  (行タップ=手牌・副露を展開/配牌編集) ├──────────────────────────┤
│                               │ [ツモ切り] [リーチ] [流局]     │
│                               │ [ロン][ツモ][ポン][チー][カン]  │
└───────────────────────────────┴────────────────────────────┘
```

- 右側: **牌パレット37種+「?」**。10列×4行、常時表示。すべて1タップ。
  赤5は 0m/0p/0s として独立ボタン(Mリーグは赤各1枚なので使用済みなら自動グレーアウト)。
- 左側: 4人の状態(名前・点数・風・リーチ棒)+**河のミニ表示を常時**。放送では河が
  見えないため、アプリの河が「ここまで記録した」の唯一の照合手段になる(実況の
  「◯◯を切りました」と河末尾を突き合わせる)。副露は河の行内に並べる。
  手番の人をハイライト。行タップでその人の手牌(未知スロットは裏牌)と
  「配牌編集モード」を展開。
- `[↩︎]` = 取り消し(イベント単位で何段でも戻れる)。`[⋮]` = メニュー
  (新ドラを入力(カン後など) / 流局にする / 前の局の穴を埋める(確定局がある時のみ) /
  試合終了として保存(順位精算) / 記録を保存して終了 / この記録を破棄して終了)。
- 上部ガイド行が常に「今なにを入力すべきか」を1行で示す。

## 4. 操作フロー

### 4-1. 局の開始
1. **ドラ牌**をパレットで1タップ(放送のドラ表示に合わせる。DBに保存する
   ドラ表示牌へは内部で逆変換: ドラ→その1つ前の牌。カンドラも同様)。
2. すぐ通常巡へ(配牌入力を待たない — 後述の遅延入力)。

### 4-2. 通常巡(全操作の9割)
状態は「ツモ待ち」→「打牌待ち」の2つを行き来する。手番は自動で回る。

- **ツモ切り(最頻)**: ツモった牌をパレットでタップ → **同じ牌をもう一度タップ**で
  ツモ切り確定(`[ツモ切り]` ボタンでも可)。**同じ場所の連続2タップ**で指の移動が無い。
  誤操作は `[↩︎]` で戻れる。
- **手番中の視覚表現**(2026-07-30 変更): ツモ〜打牌の間(鳴き後の打牌待ち含む)、
  その選手の行は河ではなく**手牌(既知牌+伏せ牌)+ツモ牌**を表示する。ツモ牌は
  間隔を空けて横に緑グローで置く(対局画面と同じ見え方)。打牌すると河表示に戻る。
- **手出し**: ツモ牌タップ → 切った牌をパレットでタップ。2タップ。
  (左の手牌表示の牌は直接タップできない。行タップは配牌編集モードの切り替え)
- **リーチ宣言**: ツモ牌タップ → `[リーチ]` → 切った牌タップ。3タップ。
  (宣言牌の横向き・供託・1000点減算・以降のツモ切り強制は自動)
- ツモ牌が画面で確認できなかったら `[?]`(不明ツモ)。後から埋められる。
- リーチ後の選手も**通常と同じ2タップ**(ツモ牌タップ→もう一度タップでツモ切り)。
  当初は1タップ自動確定としていたが、「河に出てから[ツモ]和了」になる違和感と、
  ツモ和了・暗槓に割り込めない問題があり廃止(2026-07-30)。リーチ中は手出しを
  受け付けない(ツモ切りのみ)。不明ツモを既知牌でツモ切りしたときは
  ツモ牌=打牌なので、ツモイベントも同時に確定する。

### 4-3. 鳴き
直前の打牌に対して:
- `[ポン]` → 鳴いた人をタップ(4人行から選択)→ 完了。
  晒す2枚は自動(赤5絡みのときだけ「赤を含む?」の2択を出す)。
- `[チー]` → 鳴けるのは下家固定なので人選択なし → 順子の形を選ぶ
  (候補は engine/call_options.dart の `allChiForms` で列挙。赤5の有無で形が増える)。
- `[カン]` → 大明槓(直前打牌に対して・人選択)。
  自分の手番中(打牌待ち)の `[カン]` は暗槓/加槓(牌種をパレットでタップ)。
  カン後の嶺上ツモ・打牌は通常巡と同じ流れ。新ドラは `[⋮]`→「新ドラを入力」で
  入力モードに切り替えてからパレットをタップ(ツモ待ち中のパレットタップはツモ入力に
  なるため)。表ドラの枚数は「1+カン数」までに制限される。
- 鳴きで晒された牌は手牌の既知情報として**自動で配牌に逆算反映**される。

### 4-4. 和了
- **ロン**: `[ロン]` → 和了した人をタップ → 手牌完成画面へ。
  (Mリーグは「アガリ者は一局に1人」=頭ハネなので、ダブロンの入力は無い)
- **ツモ**: 打牌待ち状態で `[ツモ]` → 手牌完成画面へ。
- **手牌完成画面**: 和了者の13枚を表示し、未知スロットが残っていればパレットで補完する
  (和了時は実写で手牌が開示される。放送は結果表示でしばらく止まるので、ここは
  生放送でも比較的写す時間がある)。リーチ和了なら裏ドラもここでタップ。
  読み取りきれなかったときは「?」を残したまま保存できるが、手牌が欠けた和了は
  役の自動判定ができないため、その場合のみ点数(と親/子・ツモ/ロン)を手動入力する。
  ただし包(責任払い)が確定している和了は手動点数を受け付けず、手牌の入力が必須。
- 役・符・点数・供託回収・本場加算は**完全自動**(evaluateWin/calcPayment)。
  結果を1画面で確認 → 次局へ。Mリーグにアガリやめ・テンパイやめは無い
  (第12条-2: 連荘は強制)ので、南4局は親が流れたときだけ半荘終了になる。
  「試合終了(精算)」ボタンは記録を打ち切るための操作で、ルール上の選択ではない。

### 4-5. 流局
- 残り山カウントは自動(70から減算)。最後の打牌が終わると「山が無い — ロンか流局を
  選んで」と案内され、`[流局]` ボタン(またはメニュー「流局にする」)で流局処理へ
  進む(河底ロンの余地を残すため自動遷移はしない)。
- テンパイ者はチェックボックス付きダイアログで選ぶ。リーチ者は必ずテンパイとして
  自動チェック・変更不可。続けてテンパイ者ごとに開示手牌を写す画面(スキップ可)
  → ノーテン罰符・親継続/親流れは自動。
- 途中流局は無い(Mリーグルール: 九種九牌・四風連打などの途中流局は不採用。
  対戦用GameEngineにも実装されていない)。

### 4-6. 配牌の遅延入力と自動逆算(本設計の核)

配牌52枚を1巡目に写すのは不可能なので、**全員「未知13枚」から始めて徐々に確定**させる:

1. **自動逆算**(主): 手出しで切られた牌・鳴きで晒された牌・和了/流局時に開示された牌は
   「その人の手にあったはず」なので、未知スロットが自動で埋まる。
   リーチ者・和了者・流局時テンパイ者は最終的にほぼ完全確定する。
2. **手動補完**(従): 手牌が実写で映るのは基本的にその人の手番のときだけで、手番中は
   ツモ・打牌の記録が優先されるため、**止めずに視聴しながらの手動補完はほぼ不可能**。
   主用途のVOD視聴では、手牌が映ったところで一時停止→左の行をタップ→配牌編集モードで
   映った手牌を写す(パレット連打で未知スロットが順に埋まり、自動ソート)。
3. 局終了時に未知が残っていても**そのまま保存できる**(本家DBにも配牌欠損局があり、
   ビューア・ゴーストの山再構成は欠損に耐性がある)。
   降りて手を開かなかった選手の手牌は原理的に確定しない — それで正常。

**完全牌譜に仕上げるための後埋め(2026-07-30 実装)**:
- **結果画面から「牌を埋める」** — 和了・流局で手牌が開示された直後に、結果表示を
  一時的に閉じて「?」タップ・手牌の写しができる(埋め終えたら[結果へ]→次の局へ)。
- **前の局の穴を埋める**(メニュー) — 確定済みの局のイベント列を試合中は保持しており、
  局を選んで(「?n・伏せm / 完全」表示付き)開き直し、「?」と手牌だけを後埋めできる。
  点数は変わらないので、その局だけ安全に再エクスポート・上書き保存される。
- **生イベント列を保存JSONに同梱**(`rec_kyokus`) — 保存後の編集・記録の中断再開
  (構想③・別途検討)の布石。ビューアは未知キーとして無視する。

注意: 自動逆算で確定するのは「配牌+それまでの不明ツモのどれか」なので、内部的には
「この人の手にこの牌があった」という集合として持ち、保存時に配牌イベントへ割り付ける。

### 4-7. 間違えたとき
- `[↩︎]` でイベント単位のアンドゥ(局内は何段でも)。
- 手遅れの取りこぼしは「前の局の穴を埋める」(§4-6)で後から埋める。
- 「この局を破棄→点数を手動調整して次局から再開」は**未実装**(今後の課題)。
  現状のメニューにある破棄は「この記録を破棄して終了」(記録全体の破棄)のみ。

## 5. タップ数の見積り(1局あたり)

| 操作 | 回数 | タップ |
|---|---|---|
| ドラ表示 | 1 | 1 |
| 通常巡(ツモ切り2 / 手出し2 / リーチ後2) | 〜70巡 | 〜140 |
| 鳴き | 〜4回 | 〜12 |
| 和了 or 流局処理 | 1 | 5〜15 |
| 配牌手動補完(逆算残り) | 〜30枚 | 〜35 |
| 合計 | | **〜180タップ / 10〜15分** |

1分あたり15タップ程度。放送のテンポ(1打牌5〜10秒)に対して余裕がある。

## 6. データ仕様

- 保存形式: MyPaifuStore と同じ本家DBスキーマ互換JSON。ID接頭辞は `REC_`。
- kyoku events は paifu-compat の規約に完全準拠(reachは宣言打牌の前 /
  agari points=供託本場込み / ツモ和了牌 `t` / カンドラ即めくり / block位置規約)。
- 不明ツモ・配牌欠損は「イベント欠落」として保存(本家DBの欠損局と同じ扱い)。
- gamePlayers は入力名(疑似ネーム含む)。成績表・スタッツは既存ロジックがそのまま動く。

## 7. 規模感とリスク

規模感: **L**(記録状態機械 + 記録画面UI + セットアップ + 保存/ビューア接続)。

- 最大のリスクは記録画面の情報密度(SE横667ptにパレット37+4人分の状態)。
  iPhone SEでは手牌ミニ表示をかなり小さくする必要がある。実機確認を早めに行う。
- 記録エンジンはGameEngine非依存の新規実装になるが、点数・役・ルール判定は
  既存engine部品(evaluateWin/calcPayment/シャンテン)を呼ぶだけで済む。
- 保存前の整合性検証として、完成した局JSONをReplaySessionで機械再生してみる
  「セルフチェック」を record_roundtrip_test に組み込み済み。

## 8. 決定事項(2026-07-29 すべて確定)

- 左パネルの常時表示は**河優先** — 放送で河が見えない以上、アプリの河が唯一の
  照合手段のため。手牌は行タップで展開。
- 主用途は**VOD(巻き戻し・一時停止しながら)で精度重視**。Mリーグは生放送中でも
  巻き戻し可・過去分の後日視聴も可のため。UI方針は簡略操作を維持し、熟練後の
  生放送リアルタイム記録も視野に入れる(専用の簡略モードは作らない)。
- ビューアの入口は**「✍️ 記録した牌譜」の別タイル** — 自分の対局(実プレイの記録)と
  放送の記録(他人の試合)はデータの性質が違うため混ぜない(2026-09-15 のメニュー
  グループ化で、両者は「🀄 自分の対局・記録した牌譜」グループ内の別タイルになった)。

## 追補: 牌譜DBのスキーマ変更への備え(2026-10-02)

配布元(konoui/m-league-game-db)は 2026-10-01 リリースでテーブル名3件・列名十数件を一斉に
改名し、配牌の表記も `,` 区切りに変えた(配布元 DB_CHANGELOG.md)。アプリは更新検知で新DBを
そのまま取り込み、ビューアが丸ごと動かない状態がユーザーに届いた(docs/failure-log.md
2026-10-02)。再発に備えて次の仕組みを入れた(ユーザー決定)。

### 取り込み時の検査と巻き戻し

- `lib/paifu/db_schema.dart` の `DbSchema.required` に「アプリが読むテーブル → 列」を持つ。
- ダウンロード後、展開した DB を置き換える**前**に `schemaProblems` で検査し、足りなければ
  今の DB とタグを保持したまま `PaifuSchemaUnsupported`(「この牌譜バージョンにはまだ対応して
  いません。今の牌譜はそのまま使えます」)を出す。拒否したタグは `database.rejected` に覚え、
  同じ版に「更新あり」を出し続けず「未対応の更新あり(アプリ側の対応待ち)」と表示する。
- 起動時(牌譜閲覧モードの表示時)にも今ある DB を同じ検査に掛け、読めない形式なら理由を
  表示してビューア・読みクイズのボタンを無効にする(旧アプリ+新DB の組み合わせでも落ちない)。

### 改名への追従は「変換表」で、無理なら「マイグレーション」

- **DB側**: 改名され得る識別子は `DbSchema` の定数だけに書き、SQL は定数を参照する。配布元が
  改名したら定数を直し、`check-paifu-db-schema` スキルで検査して終わり。列の意味や分割が
  変わる変更が来たときに初めて読み出しコード側を直す。
- **自分牌譜JSON側**: キー名はアプリ内部の名前で固定し、DB の改名に追従**しない**
  (保存済みファイルを壊さないため)。DB との対応は `own_paifu_format.dart` の
  `internalToDbKey` に変換表として持つ(DB 一本化のときの変換に使う)。内部形式そのものを
  変えざるを得ないときは `ownPaifuFormatVersion` を上げ、`migrateOwnPaifu` に旧版→新版の変換を
  1段足す。保存時に `format` を付け、読み込み時にその場で繰り上げる(ファイルは書き戻さない)。
  2026-10-02 時点の版は 1(版0=キー無しの旧ファイルはキー変更なしで版1扱い)。
