# 麻雀卓(mahjong_taku)

スマホ用4人打ちリーチ麻雀(**Mリーグルール専用**)と、Mリーグ公式戦の牌譜ビューア。
Flutter製、Android / iOS 対応、**横画面専用**。

[Mリーグ](https://m-league.jp/)は 2018 年に始まった日本のプロ麻雀リーグ。
本アプリの対戦ルールは [Mリーグの競技規定](https://m-league.jp/about/)に合わせ、牌譜ビューアは
[konoui/m-league-game-db](https://github.com/konoui/m-league-game-db) が公開している公式戦の牌譜データを読みます。
このアプリの作者はMリーグとも牌譜データの配布元とも無関係のファンで、本アプリは非公式です。

このリポジトリは「作者がコードを読まない完全バイブコーディングでどこまで作れるか」の
実験でもあります。開発方針・失敗談・設計メモは [docs/](docs/) にそのまま置いてあります
(入口: [docs/development-policy.md](docs/development-policy.md))。

## できること

### 対戦モード

- **ひとりで打つ** — CPU3人との対局。
- **部屋を作る** — この端末がホストになり部屋を公開。1〜4人で開始でき、足りない席はCPUが代打。
  ホストは席に着かず観戦だけする「ギャラリー」も可(その場合ゲスト枠は4)。
- **部屋に入る** — 見つかった部屋一覧から選ぶ。接続経路は3系統を自動で併用:
  - **Wi-Fi経由**(mDNSで自動発見、IPアドレスの手入力も可)
  - **近距離接続**(Wi-Fi不要。iPhone同士=Multipeer、Android同士=Wi-Fi Direct)
  - **BLE接続**(Wi-Fi不要。iPhone / Android 混在可)
- **対局中の補助**: 手牌の色分け(現物=青、喰い替え不可=灰、攻めの推奨打牌=赤点滅、ドラ強調)、
  リーチ候補牌の上に待ち牌と残り枚数、フリテン表示、「アドバイス」(攻撃: シャンテン・受け入れ・狙える役、
  守備: 警戒相手・危険牌・通りやすい牌・通ったスジ)、中央パネルから「順位表 / 逆転の目安」(逆転に必要な手を
  ツモ/ロン別に表示)、顔文字(9種、全員に届く)。
- **試合の進行**: 連戦(ホストが「次の試合へ」)、毎試合の場決め(席をシャッフル)、試合ごとのゲームスタッツと
  総合成績表(素点・ポイント・アガリ・リーチ・放銃)、試合の中断と復帰(ホストのみ。復帰ロビーで中断メンバーを待ち、
  未合流はCPUが代行)。
- **切断・観戦**: 対局中に誰かが切断するとCPUが即座に代打し、同じ名前で入り直すと席に復帰(切断画面の「再接続」、
  または部屋に入り直す)。開始後の部屋に入ると観戦希望になり、ホストの許可後に席の視点を選んで観戦できる。
- **早見表**: 役一覧・点数表・符計算・牌一覧・基本用語集・このアプリについて(クレジット)。
- **自分の対局の保存**: ホストとソロの端末に牌譜が自動で貯まり、牌譜ビューアで再生できる。

### 接続経路の使い分け

| 状況 | 方法 |
|---|---|
| 共通のWi-Fiがある | そのまま(自動発見) |
| Wi-Fiがない・iPhone同士 | 近距離接続(Multipeer Connectivity)、または BLE |
| Wi-Fiがない・Android同士 | 近距離接続(Wi-Fi Direct。ホストが受けられるのは1人)、または BLE |
| Wi-Fiがない・iPhoneとAndroid混在 | **BLE接続**。または誰か1人のスマホでテザリングをONにして全員接続 |

### 牌譜閲覧モード

- **最新牌譜ダウンロード** — Mリーグ全試合の牌譜DB(zip 約200MB)を配布元の最新リリースから取得。
  5xx・通信断は自動で最大3回まで再試行。起動時に1回だけ更新の有無を確認して「更新あり」を出す。
  アプリが対応していない形式のリリースは取り込まず、今のDBを保持する。
- **牌譜ビューア** — シーズン → ステージ → 試合日 → 試合 → 視点の選手の順に選んで再生。
  自動再生 / ポーズ、一手・一局の送り戻し、お気に入り局(★)の登録、総合成績表。
  この端末で打った対局(自動保存)と、手動で記録した牌譜も同じビューアで再生。
- **ゴーストモード** — ポーズ中の任意の手巡から、観戦中の選手(または全席)を自分で打つ。記録どおりに打てなくなった
  他家はCPUが代打。局が終わると「実際」と「今回」の結果を比較し、同じ局面での通算(和了・放銃・流局)も表示。
- **局を探す** — お気に入り局のある試合、アガリ検索(役満・三倍満・倍満・リーチ一発・ドラ7以上・裏ドラ3以上・
  裸単騎・地獄単騎リーチ)、通らなかったリーチ、天和・地和チャンス(配牌テンパイ)、見逃しからのロン和了、
  全員集合からの決着(オーラス開始時に全員2万点台で決着)。一覧をタップするとその局を当事者の視点で再生。
- **読みクイズ** — 流局局を出題し、4家の手牌を伏せた卓からテンパイ / イーシャンテン / それ以外と待ち牌を当てる。
  難易度は「かんたん」(リーチのかかった局、リーチ者は待ち当て)、「ふつう」(すべての流局局)、
  「むずかしい」(リーチのない局を流局の2〜3巡前で)。答え合わせ後にその局をビューアで再生できる。
- **手動牌譜記録** — 放送対局などを見ながら、4人の河・鳴き・リーチ・和了・流局を入力して牌譜にする。
  牌パレット(37種+不明「?」)、途中局からの開始、過去局の穴埋め、和了手牌からの自動点数計算(読み取れないときは手入力)、
  試合終了として順位精算。

## できないこと・制限

把握している範囲で、現時点の実装に無いもの・制限のあるものです。

**対局・設定**
- ルールの選択は東風戦 / 半荘戦のみ。開始点(25,000点固定)やCPUの強さは変えられない。
- 名前と東風 / 半荘の選択はアプリを閉じると消える(端末に保存しない)。総合成績表(試合履歴)と読みクイズの
  通算成績もセッション中だけ。
- ソロ対局の中断からの復帰は、ネット対戦用の復帰ロビーを経由する。
- 観戦者は打牌・顔文字・「次へ」を使えない。ギャラリー(ホストの観戦)の指定は開始前のロビーだけ。

**通信**
- 近距離接続は iPhone と Android の直結ができない。Android同士ではホストが近距離で受けられるのは1人まで
  (プラグインの1対1ソケット制約。残りは Wi-Fi か BLE)。
- BLE の Android ホストは部屋一覧に「BLEの卓」と出る(端末の Bluetooth 名を書き換えないため部屋名を広告に載せていない)。
  入室後に部屋名を受け取る。
- 切断後の再接続は自動ではなく、切断画面の「再接続」を押すか部屋に入り直す。
- 全員が同じ版のアプリである必要がある(プロトコル版が違うと入室できない)。
- 自分の対局の牌譜が残るのはホストとソロの端末だけ。ゲストの端末には残らない。

**牌譜**
- 牌譜の書き出し・共有(ファイル・クリップボード)はできない。
- 再生速度の変更、再生中の視点切替、局番号を指定したジャンプはできない(視点は再生前に選ぶ。全員ゴースト中のみ
  手番の席へ自動で切り替わる)。
- 牌譜DBの更新確認は起動時の1回だけで、DBが無いときやオフラインのときは行わない。

**手動記録**
- ダブロン・西入の入力は無い(Mリーグルールに存在しないため)。海底牌でのリーチは入力できない。

**配布**
- アプリストアでは配布していない。各自でビルドして入れる前提(iOS は署名設定が必要)。
- 横画面専用。

## 実装ルール(Mリーグ準拠)

完全にMリーグルールに従う。他のルール実装は考慮していない。

## アーキテクチャ

```
lib/
  engine/   純Dartのルールエンジン(牌・和了/シャンテン・役・点数・局進行・CPU AI・表示文言)
  net/      対戦通信(ホスト=権威サーバー方式。WebSocket / 近距離 / BLE の3経路と共通の整形層)
  session/  UIと対局をつなぐセッション抽象 GameSession とソロ実装、中断・復帰の保存
            (ホスト・クライアントの実装は net/、牌譜再生の実装は paifu/)
  paifu/    牌譜DBの取得・読み出し・検索、再生(ゴースト含む)、読みクイズの出題
  record/   手動牌譜記録のエンジンと保存
  ui/       画面(ホーム・ロビー・対局・牌譜ビューア・クイズ・手動記録・早見表)
tool/       牌譜DBに対する調査用の Dart スクリプト
test/       ロジックテスト(この実験では人のコードレビューの代わりになる回帰の柱)
```

- ホスト端末の `GameEngine` が唯一の正で、各席には `PlayerAgent`(人間UI / CPU / ネットワーク越しのクライアント)が着席
- クライアントには席ごとの視点ビュー(他家の手牌は枚数のみ)をJSONで配信するため、覗き見不可
- 通信ポート: 47654(使用中なら自動でずらす)。mDNSサービスタイプ: `_mahjongtaku._tcp`
- 同じ意味の計算・表示規則は共有モジュールの純粋関数1箇所に置く(置き場所の一覧は [CLAUDE.md](CLAUDE.md) §2)

### 状態管理ライブラリを使っていないことについて

Riverpod などの状態管理・DI パッケージは使っていません。これは最初に設計として決めたものではなく、
後から振り返って付けた説明です(開発方針上、作者はコードを読まず、状態管理基盤を入れ替える依頼も出なかった)。

- 状態の本体は UI の外にあります。ホストの `GameEngine`(純 Dart)が唯一の正で、`GameSession` 抽象が
  `Stream<GameView>` / `Stream<TurnPrompt>` などを公開し、ソロ・ホスト・クライアント・牌譜再生・ゴーストが
  その実装になっています。UI は Stream を購読して `setState` で描き直すだけで、画面を跨ぐ状態はほぼ持ちません。
- 権威サーバー方式のため、UI は「ビューを受け取って表示し、操作を送る」クライアントに徹します。
  この形では状態が自然に Stream になり、Provider のグラフで表現する動機が薄い。
- テストの柱はエンジンとセッションの純 Dart テストで、UI 層で依存を差し替える必要がありませんでした。

今後、画面を跨ぐ設定(名前の永続化・表示オプションなど)が増えて UI 層に状態が溜まり始めたら、
その時点で小さく導入する余地はあります。

### プラットフォーム設定メモ

- 横画面固定: `main.dart` の `SystemChrome` + Android `screenOrientation="sensorLandscape"` + iOS `UISupportedInterfaceOrientations`
- iOS 14+ のローカルネットワーク許可: `NSLocalNetworkUsageDescription` と `NSBonjourServices`(`_mahjongtaku._tcp`)を `Info.plist` に設定済み。初回のホスト/検索時にOSの許可ダイアログが出ます
- iOS の Bluetooth 許可: `NSBluetoothAlwaysUsageDescription` を `Info.plist` に設定済み(BLE 接続の初回に許可ダイアログが出ます)
- Android: `INTERNET` / `ACCESS_WIFI_STATE` / `CHANGE_WIFI_MULTICAST_STATE` に加え、BLE 用に
  `BLUETOOTH_SCAN` / `BLUETOOTH_CONNECT` / `BLUETOOTH_ADVERTISE`(Android 12+)と旧版向けの
  `BLUETOOTH` / `BLUETOOTH_ADMIN` / `ACCESS_FINE_LOCATION` を設定済み。初回に「付近のデバイス」の許可を求めます
- アプリアイコンの再生成: `assets/icon/` の素材を更新して `fvm dart run flutter_launcher_icons`(手順の注意は `pubspec.yaml` のコメント)
